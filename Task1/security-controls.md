# Меры защиты данных

## 1. Защита данных на разных этапах

Для новых систем «Медикаменте» необходимо предусмотреть защиту данных на всех этапах работы: от получения информации до её удаления.

| Этап | Что необходимо сделать |
|---|---|
| Сбор данных | Запрашивать только информацию, которая действительно нужна для оказания услуги. |
| Передача | Использовать защищённые соединения (TLS), ограничить обмен данными между системами. |
| Доступ | Настроить RBAC/ABAC. Каждый сотрудник должен видеть только данные, необходимые для работы. |
| Хранение | Шифровать конфиденциальные данные, ограничить доступ к файлам и настроить резервное копирование. |
| Обработка | Сохранять теги конфиденциальности при переносе данных. Не передавать медицинские сведения в системы, где они не нужны. |
| Просмотр и выгрузка | Скрывать лишние поля и ограничивать массовое скачивание документов. |
| Интеграции | Передавать лаборатории и другим партнёрам только необходимые данные. Проверять права доступа к каждому запросу. |
| Мониторинг | Записывать действия с конфиденциальными данными и уведомлять о подозрительной активности. |
| Аналитика | Использовать обезличенные данные или общую статистику. |
| Удаление | Соблюдать сроки хранения и удалять данные, которые больше не нужны и не подлежат обязательному хранению. |

При разработке новых версий необходимо автоматически проверять права доступа и отсутствие утечек через API.

## 2. Разграничение доступа сотрудников

Предлагаем следующую матрицу доступа:

| Роль | К каким данным есть доступ |
|---|---|
| Ресепшен | Записи на приём, контакты пациентов и при необходимости статус оплаты |
| Врач | Медицинские карты и анализы пациентов, которых он лечит |
| Кассир | Платежи, суммы и чеки |
| Бухгалтер | Финансовые документы, платежи и необходимые кадровые сведения |
| Склад | Закупки, остатки товаров и складские документы |
| Пациент | Собственные записи, документы, анализы и оплаты |
| IT-администратор | Управление инфраструктурой без автоматического доступа к медицинским данным |

Доступ также необходимо ограничивать по филиалу и рабочим задачам. Для исключительных ситуаций можно предусмотреть временный доступ с обязательной записью действий в журнал.

## 3. Как проверить защиту

После внедрения нужно убедиться, что:

1. Сотрудники не могут просматривать данные, которые не относятся к их работе.
2. Пациент не может получить чужую медицинскую карту через API.
3. Просмотры, изменения и выгрузки документов фиксируются в журнале.
4. Подозрительные действия, например массовое скачивание медицинских карт, вызывают уведомление.
5. Резервные копии защищены, а восстановление данных работает.

## 4. Порядок внедрения

В IT-отделе компании всего три сотрудника, поэтому меры защиты лучше внедрять постепенно.

**Первый этап — существующие системы:**
- Настроить права доступа к общим папкам и файлам через Active Directory.
- Включить аудит действий с конфиденциальными документами.
- Проверить резервное копирование и защиту файлов.
- Составить список конфиденциальных данных.

**Второй этап — новые сервисы:**
- Реализовать проверку прав через RBAC/ABAC.
- Защитить API и интеграцию с лабораторией.
- Добавить автоматические тесты безопасности.

**Третий этап — аналитика:**
- Внедрить каталог данных и автоматическое тегирование.
- Настроить отслеживание перемещения данных (Data Lineage).
- Использовать обезличенные данные для BI/ML.

Такой подход позволит сначала устранить основные риски существующей системы, а затем постепенно внедрять дополнительные механизмы безопасности.
