# Механизм тегирования и Data Lineage

## 1. Тегирование данных

Для защиты конфиденциальной информации предлагаем назначать данным специальные метки (теги). Они помогут определить, какие данные хранятся в системе и кто может с ними работать.

Основные теги:

| Тег | Значение |
|---|---|
| `classification` | Уровень конфиденциальности: INTERNAL, CONFIDENTIAL, RESTRICTED |
| `domain` | Категория: пациенты, медицина, финансы, сотрудники, склад |
| `personal_data` | Содержит ли информация персональные данные |
| `medical_secret` | Относится ли информация к врачебной тайне |
| `owner` | Ответственное подразделение |
| `allowed_roles` | Какие роли могут получить доступ |
| `retention_policy` | Срок и правила хранения |
| `source_asset` | Источник данных |

Например, медицинская карта получает теги `RESTRICTED`, `MEDICAL` и `personal_data=yes`.

## 2. Как работает механизм

1. **Поиск данных.** Проверяем Excel, документы, общие папки и базы 1С.
2. **Назначение тегов.** Система предлагает теги, ответственный сотрудник их подтверждает.
3. **Передача данных.** При копировании и передаче теги сохраняются.
4. **Контроль доступа.** Система проверяет роль сотрудника и его право работать с конкретными данными.
5. **Аудит.** Записываем, кто, когда и к каким данным обращался, без сохранения медицинских сведений в логах.
6. **Проверка релизов.** Автоматически проверяем, что пользователи не получают доступ к чужим данным.

## 3. Инструменты

| Инструмент | Назначение |
|---|---|
| OpenMetadata | Каталог данных, теги и отслеживание источников |
| Presidio | Поиск персональных данных |
| AD/LDAP + RBAC/ABAC | Управление доступом |
| Vault | Хранение ключей и секретов |
| Wazuh | Аудит и уведомления о подозрительных действиях |
| CI/CD-тесты | Проверка прав доступа перед релизом |

Это предлагаемые инструменты для To-Be, а не существующие системы компании.

## 4. Правила доступа

- **Врач** — медицинские карты пациентов, с которыми работает.
- **Ресепшен** — записи на приём и контакты, без диагнозов.
- **Кассир** — суммы платежей и чеки, без медицинских данных.
- **Пациент** — только собственные документы.
- **Аналитик** — обезличенные данные и статистика.

Если доступ не разрешён явно, система должна его запретить.

## 5. Data Lineage — отслеживание данных

Data Lineage позволяет видеть, откуда данные поступили, как изменялись и куда передавались.

Пример:

Excel с записями → база пациентов → обработка → отчёт о посещениях.

Это необходимо для поиска копий данных, контроля выгрузок и выполнения запросов на удаление информации с учётом сроков обязательного хранения.

## 6. Проверка безопасности

- При каждом релизе — автоматические тесты прав доступа.
- Ежемесячно — анализ подозрительных обращений к медицинским данным.
- Ежеквартально — проверка ролей сотрудников и корректности тегов.

**Результат:** компания сможет контролировать доступ к конфиденциальным данным, отслеживать их перемещение и быстрее обнаруживать возможные утечки.
