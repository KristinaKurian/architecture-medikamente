# Аудит мер безопасности по текущим потокам

**Критерии:** наличие минимизации, контролируемого источника истины, ограничения доступа, регистрации операций, ограничений потоков, шифрования и надлежащего жизненного цикла. Заключение «не описано» не равно «отсутствует».

| Процесс | Факт As-Is | Проблема безопасности | Целевая практика / требование | Результат проверки |
|---|---|---|---|---|
| Приём и договор | Excel и сканы на общем диске, ручной ввод | Медицинские/личные данные в общих файловых пространствах | Privacy by Design, минимизация данных и разграничение доступа | **Установлено:** общие файлы и ручной ввод; фактические ACL уточнить |
| Запись пациента | Excel-журналы | Утечки самого факта обращения/контактов через журнал | Ст. 13 323-ФЗ; минимум данных по ролям | **Установлено:** журналы в Excel; правила доступа к строкам не описаны |
| Медкарты и анализы | JPG/PDF, общий диск, аудит отсутствует | Нет прослеживаемости просмотра и редактирования медзаписей | 152-ФЗ ст. 10/19; 323-ФЗ ст. 13; учёт событий | **Установлено:** нет аудита; ограничения по данным не реализованы |
| Оплата | Дублирование Excel и 1C | Лишние копии платежной информации, несогласованность | Минимизация, ограничение распространения и консистентность | **Установлено:** дублирование |
| ККМ→1C | TCP/IP+OLE | Нужно проверить сегментацию, сервисную учётку и защиту передачи | Secure integration, принцип наименьших привилегий | **Требует проверки:** защита канала не описана |
| Кадры/зарплата | 1C в файловом режиме | Данные персонала должны иметь отдельный scope | RBAC, защита файловой БД, аудит | **Требует проверки:** фактические права/резервирование неизвестны |
| Закупки | 1C склад ↔ 1C бухгалтерия | Нет описания контроля экспорта/пересылки | Ограничение доменных потоков, коммерческая тайна | **Требует проверки:** формат интеграции неизвестен |
| Все процессы | Единый физический сервер в офисе | Единая точка отказа, риски пожара/диска/доступа | Доступность, резервное копирование, восстановление | **Установлено:** единый сервер; резервное копирование неизвестно |
| Все процессы | Доменная аутентификация, ограничения систем не описаны | Учетная запись в AD не определяет необходимость просмотра медкарты | RBAC + ABAC на объекте, default deny | **Установлено:** нет дополнительных системных ограничений |
| Все процессы | Невыполненный контроль внутренних потоков | Неконтролируемая передача категорий между доменами | DLP, data contracts, lineage | **Установлено:** потоками не управляют |
| Все процессы | Нет аудита действий в IT-системах | Нельзя расследовать утечку и нетипичные просмотры | Контроль событий безопасности, SIEM | **Установлено:** отсутствие требуемого аудита |
| Все процессы | Сроки, правовые основания и классификатор не описаны | Риск обработки избыточных/застарелых данных | 152-ФЗ ст. 5, 6, 21; обработка запросов субъекта | **Требует проверки:** юридические документы и сроки не представлены |
| Будущий BI/ML | План озера данных из Excel | Риск тиражирования медицинских данных в обучение | Purpose limitation, privacy review, обезличивание | **Проектный риск**, не факт нарушения As-Is |
| Будущий пациентский API | Запланирован доступ к медданным | Риск BOLA/IDOR (получить чужую карту по ID) | Проверка owner/representative на сервере | **Проектный риск**, пока нет API |
| Будущий API лаборатории | Планируемая интеграция | Риск передачи лишних полей, некорректной аутентификации | Контракт с allowlist полей, mTLS/подписи, сервисные роли | **Проектный риск**, пока нет API |

## Правовое сопоставление

- **152-ФЗ ст. 5:** цель и объём обработки, минимизация, сроки и актуальность данных. Для медцентра это реестр целей/полей и права, а не сбор «на всякий случай».
- **152-ФЗ ст. 10:** данные о состоянии здоровья — специальные категории ПДн, их обработка допускается только при предусмотренных законом основаниях.
- **323-ФЗ ст. 13:** врачебная тайна включает обращение за помощью, состояние здоровья и диагноз; доступ для врача должен соответствовать лечению и законной цели.
- **152-ФЗ ст. 18 ч. 5:** локализацию баз ПДн граждан РФ необходимо учитывать, особенно для будущих порталов, облаков и BI.
- **152-ФЗ ст. 19**, **ПП РФ №1119**, **приказ ФСТЭК №21:** требования к организационным и техническим мерам, определение уровня защищённости по модели угроз/типу данных/масштабу. **Уровень здесь не присваиваем**.
- **152-ФЗ ст. 21:** процедуры блокирования, уточнения, удаления и уведомления о предусмотренных законом инцидентах. План расследования должен учитывать сроки первичного уведомления 24 ч и результатов расследования 72 ч там, где применимо.

Юридический анализ не подменяет заключение ответственного за ПДн и юриста, особенно для медкарт, согласий, локализации и сроков хранения.
