# Реестр средств защиты данных

Для защиты данных «Медикаменте» часть инструментов можно использовать из существующей инфраструктуры, остальные потребуется внедрить при разработке новых сервисов.

## 1. Программные средства

| Инструмент | Для чего нужен | Статус | Приоритет |
|---|---|---|---|
| Active Directory, NTFS | Управление учётными записями и доступом к файлам | Есть, проверить настройки | Высокий |
| BitLocker | Шифрование дисков сервера | Проверить, включён ли | Высокий |
| Windows Audit | Запись действий сотрудников с файлами | Настроить | Высокий |
| Права доступа 1С | Разделение доступа бухгалтерии, кадров и склада | Есть, проверить настройки | Высокий |
| Windows Server Backup / Veeam | Резервное копирование и восстановление данных | Выбрать и настроить | Высокий |
| Firewall | Ограничение сетевого доступа к серверу, 1С и ККМ | Проверить настройки | Высокий |
| Nginx + TLS | Защита соединений нового портала и API | Добавить при разработке | Высокий |
| Vault / KMS | Безопасное хранение ключей шифрования | Добавить | Средний |
| Wazuh | Мониторинг событий безопасности и уведомления | Добавить | Средний |
| Gitleaks, Semgrep | Поиск секретов и проблем безопасности в коде | Добавить в CI/CD | Средний |
| Presidio | Поиск персональных данных в файлах | При необходимости | Низкий |
| OpenMetadata | Каталог данных, теги и отслеживание их перемещения | При внедрении аналитики | Низкий |

## 2. Аппаратные средства

| Оборудование | Для чего нужно | Статус | Приоритет |
|---|---|---|---|
| Сервер Windows Server 2022 | Размещение существующих систем и файлов | Есть, проверить состояние | Высокий |
| Межсетевой экран и сетевое оборудование | Разделение сети сотрудников, серверов и ККМ | Проверить возможности | Высокий |
| Отдельное хранилище резервных копий | Сохранение данных при сбоях основного сервера | Добавить | Высокий |
| ИБП | Защита сервера от отключений электричества | Проверить наличие | Средний |
| Дополнительные серверы | Распределение нагрузки при открытии филиалов | По мере роста | Низкий |
| HSM | Аппаратная защита ключей шифрования | По результатам оценки требований | При необходимости |

## 3. Порядок внедрения

**Первый этап — защита существующих систем**

- Проверить права доступа в AD, файловом сервере и 1С.
- Включить шифрование дисков и аудит действий.
- Настроить защищённые резервные копии.
- Ограничить сетевые подключения к серверу и ККМ.

**Второй этап — запуск новых сервисов**

- Настроить HTTPS/TLS для портала и API.
- Добавить централизованное управление ключами.
- Подключить мониторинг безопасности и проверки кода в CI/CD.

**Третий этап — развитие системы**

- Внедрить автоматический поиск конфиденциальных данных.
- Добавить каталог данных и отслеживание их перемещения.
- Масштабировать инфраструктуру при открытии филиалов.

## 4. Что проверить перед внедрением

Перед выбором инструментов нужно проверить существующие лицензии, совместимость с 1С и ККМ, а также определить требования к защите данных.

Не все перечисленные средства нужно устанавливать сразу. Выбор конкретных решений, включая необходимость сертифицированных средств защиты, зависит от модели угроз и требований законодательства.

**Основной приоритет** — сначала использовать возможности Windows Server, AD и 1С, защитить резервные копии и сетевые соединения. Остальные инструменты внедрять по мере развития системы.
